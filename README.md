# igit — 本地 git 仓库扫描与整理工具

在 Windows 电脑上扫出散落各处的 git 仓库。你可以像逛文件目录一样穿梭浏览，查看未提交改动、排查重复克隆、打标签、分组归档。处理完的仓库不再打扰你。

单个 exe 文件，无运行时依赖。数据保存在两个纯文本 JSON 文件中，随手拷走就能迁移。

> 详细使用指导请阅读 [docs/USAGE.md](docs/USAGE.md)。

## 2. 编译与安装

在终端执行：

```bash
go build -trimpath -ldflags="-s -w" -o igit.exe .
```

也可以直接在资源管理器双击运行 **`build.cmd`**。编译后单个文件约 4 MB。运行单元测试：`go test ./...`。

建议把 `igit.exe` 放到固定目录并加入系统 PATH，例如：

```cmd
mkdir "%LOCALAPPDATA%\igit"
copy igit.exe "%LOCALAPPDATA%\igit\"
```

## 3. 三分钟上手

### 步骤 1：添加扫描目录并开始扫描

```cmd
rem 1) 自动探测电脑各盘，寻找放置代码的目录（只看两层，速度很快）
igit config discover

rem 2) 添加你常用的代码目录（可多次添加）
igit config add-root D:\work
igit config add-root D:\repos

rem 3) 执行扫描
igit scan
```

### 步骤 2：查看扫描结果

```cmd
rem 看清单：默认只列出「待处理」的仓库
igit list

rem 看看哪些仓库有未提交的改动
igit list --dirty

rem 按磁盘目录树查看分布，看看仓库都堆在哪里
igit tree --brief --depth=2

rem 查重复克隆：看看哪些仓库在不同目录下被重复克隆了多次
igit dupes
```

### 步骤 3：交互式整理或随心游走

```cmd
rem 方式 A：进入全屏交互面板，按上下键浏览，按快捷键标记与归档
igit triage

rem 方式 B：直接敲 igit 进入交互命令行，像在文件系统里一样穿梭
igit
```

## 4. 交互命令行与「来时路」

仓库多了之后，每次都从全局清单里找会非常累。直接运行 `igit`（不带任何子命令）就会进入交互会话。

### 怎么移动

会话支持你熟悉的命令：

- `cd <目录名>`：走进某个子目录。
- `cd <仓库名>`：直接走进某个具体仓库。
- `cd group:<分组名>`：走进某个逻辑分组（例如 `cd group:核心业务`）。
- `cd tag:<标签名>`：走进某个标签（例如 `cd tag:待推送`）。
- `cd ..`：原路返回上一层。
- `cd -`：切回上一次所在的位置。
- `cd /`：一键回到全局根目录。
- `ls`：看当前位置底下有哪些子目录、子仓库或分组。
- `pwd`：打印当前位置和完整的来时路。

提示符会清晰显示你**怎么走过来的（来时路）**以及当前范围内包含多少个仓库：

```
igit [root · 190 个仓库] > cd work
igit [file:D:\work · 85 个仓库] > cd backend
igit [file:D:\work] -> [repo:backend] > pwd
当前节点: 仓库 backend
来时路: [file:D:\work] -> [repo:backend] (敲 cd .. 返回 work)
```

位置只在会话内存活，输入 `exit` 退出即销毁，不会修改系统当前工作目录，也不写磁盘配置。

### 走进去之后能做什么

你走到了哪里，后面的命令就默认对哪里生效：

1. **当你停在单个仓库上时**：
   后面的命令**不需要再重复输入仓库名字**，直接对它操作：
   - 敲 `tig`：直接新开窗口用 tig 查看这个仓库的提交与改动。
   - 敲 `open`：直接在资源管理器里打开这个仓库的文件夹。
   - 敲 `stats`：直接查看这个仓库的详细情况（分支、改动文件数、最新提交、体积等）。
   - 敲 `dupes`：精准排查这个仓库在全盘其他地方是否有重复克隆。
   - 敲 `scan`：原地重新检测这一个仓库的最新状态。
   - 敲 `group <分组名>` / `group clear`：把当前仓库划入分组或移出分组。
   - 敲 `tag add <标签>` / `tag rm <标签>`：为当前仓库追加或删除标签。
   - 敲 `status <状态>` / `note <备注>`：更新处理状态或记一笔备忘。

2. **当你停在某个目录、分组或标签下时**：
   后面的命令**只针对当前范围内的这批仓库**：
   - `list` / `tree`：只看当前这批仓库的列表或目录树。
   - `stats`：统计当前这批仓库的总体数字（多少个仓库、多少个未提交改动）。
   - `triage`：打开全屏面板，范围收窄在当前这批仓库里，逐个处理。
   - `export`：只导出当前这批仓库的清单。
   - `scan`（在目录下）：只重新扫描这个目录子树，高频刷新非常快。

3. **全局查阅命令随时可用**：
   不管当前停在哪里，这些辅助命令随时可以敲：
   - `group`：查看全盘现存的所有分组及仓库数量。
   - `group new <名>` / `group rename <旧> <新>`：新建或重命名分组。
   - `tag`：查看全盘打过的所有标签及使用次数。
   - `dirs`：查看当前设置过的所有隐藏/折叠目录规则。

## 5. 对整块目录表态：hide 与 fold

仓库很多时，逐个标记太费力气。大部分时候你其实想对整个目录表态：

- **`hide`（隐藏目录）**：彻底不看这个目录。扫描时直接跳过整棵树，清单里再也不出现。
- **`fold`（折叠目录）**：收拢成一行。知道底下有多少个仓库就行，不展开占地方。

```cmd
igit hide D:\repos\temp_clones            :: 临时克隆目录，彻底不看
igit hide D:\repos\vendor --note="第三方" :: 加句说明为什么隐藏
igit fold D:\work\archives                :: 归档目录，只留一行看数量
igit dirs                                 :: 查看当前设置的所有规则
igit unhide D:\repos\temp_clones          :: 取消隐藏
igit unfold D:\work\archives              :: 取消折叠
```

规则记录在配置中，后续新克隆进该目录的子仓库也会自动继承。

## 6. 与外部工具联动：tig 与 open

igit 负责管好「电脑里几十个仓库哪些需要留意」，单个仓库里的详细代码变更交给专业工具处理。

- **`open`**：在资源管理器中直接打开仓库目录。
  - 停在单仓节点时：直接敲 `open`；
  - 在集合中时：敲 `igit open <仓库名>`。
- **`tig`**：拉起外部终端窗口并打开 tig 查看历史。
  - 停在单仓节点时：直接敲 `tig`；
  - 智能开屏：igit 知道仓库当前处于什么状态，会自动定位到合适的界面：
    - 有未提交改动 → 开在 `status` 页面；
    - 领先远端若干个提交 → 开在未推送提交日志；
    - 没有配置远端 → 开在 `refs` 视图；
    - 其它情况 → 开在主提交历史页面。

在终端运行 `igit triage` 进入全屏整理面板。底部有常驻按键提示，按 `?` 呼出完整帮助：

```
移动   ↑/k  ↓/j  PgUp/PgDn  Home/End
多选   空格 选择/取消     A 全选    a 取消选择   Esc 清空选择
处理   S 循环状态        d 标记为已处理  w 跟进中  z 已归档  u 撤回待处理
归类   G 设置分组        T 打标签       N 写备注  x 清除分组
忽略   I 设为忽略/取消忽略
折叠   e 折叠/展开光标所在目录（临时操作，不存盘）
```

## 9. 存储与配置迁移

本工具无需安装，不写注册表，不启动系统后台服务。数据全部保存在：

- `~/.igit/config.json`：你的配置（扫描目录、排除目录、并发数等）。
- `~/.igit/state.json`：扫描发现的仓库清单及你的分组、标签、备注与处理结论。

如需更换存储路径，可设置环境变量 `IGIT_HOME=D:\my_data`，或者运行时带 `--home D:\my_data` 参数。

## 10. 设计原则

- **绝不篡改用户的 Git 仓库**：igit 只读读取 `.git` 目录和状态，绝不执行 `git push`、`git commit`、`git reset` 等任何写入命令。
- **事实与结论分开存**：扫描发现的 Git 分支、提交和改动是「客观事实」，你的分组、标签、状态是「主观结论」。无论重新扫描多少次，你的整理成果永远不会被冲掉。
- **配置纯文本可读**：数据直接以普通 JSON 文件保存，可随时用文本编辑器打开修改或备份。
- **目录规则优于逐个打标**：对成批的代码目录，直接一条 `hide` 或 `fold` 解决，简单干脆。

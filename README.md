# igit — 专为跳跃思维设计的本地 Git 仓库漫游与整理工作台

> **“当你想到什么，就敲什么，然后自然地去做，不需要先想点别的东西。”**

---

## 1. 为什么创造 igit：根源与核心哲学

作为每天与海量代码打交道的工程师，电脑各盘散落着数十甚至数百个 Git 仓库。面对这种复杂资产，人的思维往往是**跳跃性、多线且意图驱动**的：
- 常常因为一个突发念头，想找某个库验证一段逻辑；
- 或者排查改动时，临时想看看某个业务模块的同源克隆。

**传统工具的痛点在于严重的认知摩擦**：
每当念头涌现，若被迫切换到深层的文件系统目录树，或是打开臃肿缓慢的图形客户端去一层层点选，繁复的目录结构和机械操作会瞬间打断原有的心流。在这个过程中，**不仅容易滋生无意义的新念头，甚至会忘掉最初想做什么，彻底迷失在物理文件系统的路径迷宫中**。

`igit` 的诞生，就是为了从根本上卸下这种认知负荷，它由三个相互咬合的核心支柱构成：

```
                      [ 念头涌现 / Associative Intent ]
                                      │
                                      ▼
┌────────────────────────────────────────────────────────────────────────────┐
│ 1. 空间跃迁 (Dynamic Semantic Space)                                       │
│    脱离死板物理路径，将全盘仓库映射至由「分组 (Group)」与「标签 (Tag)」构成的动态语义空间。│
│    想到什么维度，直接输入直达，让仓库自然聚拢至眼前。                      │
└─────────────────────────────────────┬──────────────────────────────────────┘
                                      │ 进入仓库 (单仓聚焦)
                                      ▼
┌────────────────────────────────────────────────────────────────────────────┐
│ 2. 原位行动闭环 (In-situ Execution & Tool Escalation)                      │
│    就地快速推进：查看状态、小步提交、多远端同步，或一键唤起 tig / 资源管理器。     │
│    无需记忆命令参数，无需复制路径，原位闭环即走。                          │
└─────────────────────────────────────┬──────────────────────────────────────┘
                                      │ 顺手标记与成片整理
                                      ▼
┌────────────────────────────────────────────────────────────────────────────┐
│ 3. 低负荷标定治理 (Effortless Triage & Governance)                         │
│    为了支撑动态空间的高效运作，提供零记忆成本的标定能力：                 │
│    动词直达 + 缺参自动交互引导；对冗余目录一键 hide/fold，永久屏蔽认知噪音。│
└────────────────────────────────────────────────────────────────────────────┘
```

## 2. 核心心智模型：空间即上下文，动词即意图

在使用 `igit` 时，你**完全不需要像查阅 API 字典那样死记硬背复杂的命令参数和命令行 Flag**：

1. **空间即上下文（Scope-First）**：
   你在哪里，动作就自动对谁生效。
   - 走进单仓（`cd <仓库名>`）$\to$ 敲 `tig`、`open`、`fetch`、`push`、`group`、`tag` 全部默认直接作用于当前仓库，**无需重复敲仓库名**。
   - 站在目录或分组下 $\to$ 所有查询与操作自动收敛在该范围内。
2. **动词即意图（Intent-Driven Fallback）**：
   想做什么，直接敲动词：
   - 想分组？敲 `group`；想打标？敲 `tag`；想配置？敲 `config`；想导出？敲 `export`。
   - **如果意图明确但没有给参数，工具绝不会冷冰冰地报错抛出 Syntax Error**，而是就地弹出带编号、支持方向键光标的交互式向导，按数字或回车即可完成操作。

## 3. 三分钟上手

### 步骤 1：探测并初始化代码目录
```cmd
rem 1) 自动探测电脑各盘放置代码的高频目录（只读前两层，极速完成）
igit config discover

rem 2) 把你的工作目录加入扫描根（可多次添加）
igit config add-root D:\repos
igit config add-root D:\work

rem 3) 执行全盘索引扫描
igit scan
```

### 步骤 2：步入交互式会话（推荐日常使用）
直接运行 `igit`（不带任何参数），进入专属交互终端：
```cmd
igit
```

此时整个全盘 Git 资产便已接入动态空间，你可以随时根据念头流转：
```text
igit [root · 128 个仓库] > cd group:核心业务      :: 念头来了：看看核心业务组
igit [group:核心业务 · 12 个仓库] > lsbytag       :: 念头来了：按标签漏斗快速过滤
igit [group:核心业务] -> [repo:user-service] >    :: 锁定了目标单仓
igit ... > tig                                   :: 敲 tig，立刻新开窗口进入可视化历史
igit ... > push                                  :: 敲 push，原位多远端推送
igit ... > cd ..                                 :: 原路退回上一层
```

## 4. 核心能力一览

### ① 动态空间漫游（告别死板文件系统）
* **`cd <目标>`**：跨越物理路径与逻辑维度的万能传送门。
  - `cd work`（走向子目录）
  - `cd group:后端服务`（走进业务分组）
  - `cd tag:待联调`（走进属性标签）
  - `cd ..` 原路返回，`cd -` 在两个位置快速切换，`cd /` 瞬间回到全局根。
* **`ls`**：清晰查看当前上下文底下有哪些子目录、仓库及其实时分支与未提交改动。
* **`lsbytag`**：响应式标签多面漏斗检索，通过空格多选标签，直达目标仓库。
* **`tree`**：空间分布视图，直观呈现仓库在物理磁盘上的聚集结构。

### ② 原位行动与工具接力（单仓即刻闭环）
停在单仓节点时，无需敲入繁琐参数，凭直觉直接操作：
* **`tig`**：状态感知智能开屏。有改动直接开在 `status` 页面；领先远端开在未推送差异；其他开在主提交树。
* **`open`**：一键在系统资源管理器中打开该仓库物理路径。
* **`stats`**：打印当前单仓的完整体检档案（HEAD、分支、暂存/未暂存/未跟踪改动明细、上游同步差量）。
* **`fetch` / `pull` / `push`**：单远端直通，多远端交互式复选，带 Token 免密透传与分叉冲突提前拦截。
* **`commit`**：小步快速提交，支持原位暂存与输入说明。
* **`ignore`**：免语法记忆交互追加 `.gitignore` 规则（支持未跟踪文件 Tab 补全）。
* **`dupes`**：原地排查当前仓库在全盘其他磁盘或路径下是否存在同源重复副本。

### ③ 低负荷标定治理（持续维系动态空间）
* **`group`**：单一业务归属划分（$N:1$）。
  - 单仓下敲 `group`：弹出分组编号菜单选择或新建；更换已有分组时强制二次确认防止手滑。
  - 目录/全局下敲 `group`：自动呼出当前作用域专属的分组批量管理向导。
* **`tag`**：自由属性打标（$N:M$）。
  - 单仓下敲 `tag`：呼出多选复选框，直接按数字切换标签勾选。
* **`hide` / `fold`**：成片治理目录。
  - `hide <目录>`：彻底隐藏噪音目录（如临时构建、第三方库），全盘扫描时整树跳过。
  - `fold <目录>`：将成百上千个不常动的老仓库目录折叠为一行，只看总数不占视线。
* **`export`**：敲 `export` 回车，交互向导即刻生成治理地图与资产总览 Markdown 报告，并**自动呼出资源管理器打开结果文件夹**。

## 5. 纯粹的设计原则

1. **选项交互第一（Interaction-First）**：
   拒绝让用户成为命令行参数记忆专家。意图明确时动词直达，不确定时由交互选项（菜单/复选/向导）自然承接。
2. **客观事实与主观治理严格分离**：
   Git 仓库的分支、改动、提交是底层「客观事实」，分组、标签、备注是用户的「主观治理结论」。无论全盘重新扫描多少次，已经理好的分组与标签**绝对不会丢失**。
3. **绝不篡改仓库与纯读安全保障**：
   除用户显式发起的 `commit`/`push` 等主动 GitOps 外，检索与扫描过程完全只读，不写注册表、不驻留后台系统服务。
4. **纯文本可携带数据**：
   所有治理结论与配置仅保存在 `~/.igit/config.json` 与 `state.json`，随时可备份、迁移或直接文本查看。

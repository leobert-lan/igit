# Scope 与来时路 — 交互与导航设计说明

本文档记录 `igit` 的作用域（Scope）、来时路（Trail Stack）与上下文交互的设计规则与技术规格。

---

## 1. 设计初衷

`igit` 不仅是一个一次性扫描器，也是一个本地 Git 仓库的管理工作台。

当本地仓库达到几十甚至上百个时，用户很难总在全局大列表中操作。用户需要：
1. **局部聚焦**：能够走进某个目录、分组或具体仓库中，后续命令默认只作用于当前范围。
2. **原路回退**：清晰知道自己是从哪个目录或哪个分组走进来的，敲 `cd ..` 能按原路退回。
3. **单仓便捷操作**：走进某个单仓后，查看提交、打开文件夹、修改标签、排查重复克隆等操作不再需要反复输入仓库名字。

---

## 2. 空间模型

`igit` 中的仓库组织由两套视角构成：

```
                    [ 根 (Root) ]
                    /           \
               (物理目录)     (业务分组 / 标签)
                 /                  \
          [Dir 物理目录]        [Group 分组] / [Tag 标签]
             /      \                \         /
          [Dir]    [Repo 仓库] <------- 关联对应的仓库
                     /     \
             (无子仓:叶子)  [嵌套子仓/子模块]
```

### 2.1 物理目录
- 真实磁盘上的父级目录。
- **目录存在的充要条件**：只有下方**确实包含至少一个 Git 仓库**的目录才会出现在导航树中并允许 `cd` 进入。不包含仓库的普通空文件夹在扫描阶段已被剔除，不进入导航。
- **单仓（Repo）**：通常作为物理叶子节点。若仓库内部包含 Submodule 或嵌套克隆仓库，则同时支持继续下钻。

### 2.2 逻辑集合（分组与标签）
- **分组（Group）**：仓库的业务归属大类（一个仓库属于一个分组，如 `group:工作`）。
- **标签（Tag）**：仓库的特征切面（一个仓库可打多个标签，如 `tag:待推送`）。
- 分组和标签直接挂在根节点下，方便跨越不同磁盘目录聚合查看同类仓库。

---

## 3. 来时路（Trail Stack）模型

### 3.1 为什么需要来时路

如果只记录“当前停在哪个仓库”，系统就不知道用户是从哪里进来的。例如仓库 `scan_git` 同时属于物理目录 `D:\work` 和分组 `group:核心业务`：
- 用户如果是从 `D:\work` 走进去的，敲 `cd ..` 应该退回 `D:\work`；
- 用户如果是从 `group:核心业务` 走进去的，敲 `cd ..` 应该退回 `group:核心业务`。

因此，交互上下文必须维护一个记录访问轨迹的**来时路栈（Trail Stack）**。

### 3.2 栈结构与移动规则

```go
type TrailStep struct {
    Type  NodeType // root | dir | repo | group | tag
    Ident string   // 唯一标识（绝对路径 / 分组名 / 标签名）
    Label string   // 提示符展示名称
}
```

- **下钻进入 (`cd <目标>`)**：新步骤压栈，来时路增长。
- **原路返回 (`cd ..`)**：出栈一步，退回进入该节点前的上一层。
- **切回上一次位置 (`cd -`)**：在当前节点与上一次离开的节点之间来回跳转。
- **回到根目录 (`cd /`)**：清空调用栈，直接回到全局根。
- **查看位置 (`pwd`)**：打印当前节点类型与完整来时路链路。

会话提示符会实时展示来时路，例如：`igit [file:D:\work] -> [repo:backend] > `。

## 4. 不同位置下的命令行为

命令在不同位置下的处理遵循简单明确的直觉：

### 4.1 停在单仓节点时（仓库为默认目标）
无需重复输入仓库名，直接对当前仓库生效：
- `open`：直接在资源管理器里打开当前仓库目录。
- `tig`：直接新开终端窗口打开 tig，并按当前仓库状态自动定位开屏视图。
- `stats`：直接输出当前仓库的详细属性（分支、未提交改动明细、最新提交、体积等）。
- `dupes`：精准排查该仓库在全盘其他地方是否有相同克隆。
- `scan`：原地重新检测该单仓的最新工作区与分支状态。
- `group <名>` / `group clear`：就地划入或移出分组。
- `tag add <t>` / `tag rm <t>`：就地打标签或摘标签。
- `status <st>` / `note <txt>`：就地更新状态或记录备忘。

### 4.2 停在目录或集合节点时（范围自动收敛）
命令只对当前范围内的仓库生效：
- `list` / `tree`：只展示当前目录或分组下的仓库。
- `stats`：统计当前范围内的仓库总数、待处理数、有改动数等。
- `export`：只导出当前范围内的清单报告。
- `scan`（在目录下）：只重新扫描该目录子树，实现快速局部刷新。

### 4.3 全局查阅命令（任何位置随时可用）
无论用户停在哪个深层目录或单仓节点，均可随时查阅全局字典与规则：
- `group`：查看全盘所有分组及仓库数；`group new` / `group rename` 新建或重命名。
- `tag`：查看全盘所有标签及使用情况。
- `dirs`：查看所有目录隐藏与折叠规则。
- `config`：查看或修改扫描配置。

## 5. 操作适用矩阵

| 操作分类 | 常用指令 | 全局根 (Root) | 物理目录 (Dir) | 分组/标签 (Group/Tag) | 单仓 (Repo) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **移动浏览** | `cd` / `ls` / `pwd` | 三大入口下钻 | 逐层物理下钻 | 浏览集合内的仓库 | 叶子节点；有子仓可继续下钻 |
| **查看清单** | `list` / `tree` | 全盘列表与树 | 局部目录列表与树 | 逻辑集合列表与树 | **直接输出该单仓数据行** |
| **查看详情** | `stats` | 全盘统计概览 | 局部批次统计 | 集合批次统计 | **直接输出该单仓详细属性** |
| **查重复克隆** | `dupes` | 全盘比对查找 | 局部查找 | 集合内查找 | **精准查找该单仓在全盘的所有副本** |
| **刷新状态** | `scan` | 全盘扫描 | **局部扫描该目录** | 提示需在物理路径下刷新 | **原地重新检测该单仓** |
| **打开查看** | `open` / `tig` | 需指定仓库关键字 | 需指定仓库关键字 | 需指定仓库关键字 | **免传参数，直接打开当前单仓** |
| **分类维护** | `group` / `tag` / `status` / `note` | 查看全部或新建 | 查看全部或新建 | 查看全部或新建 | **就地对该单仓打标/分组/备忘** |
| **批量整理** | `set` | 全局匹配批量修改 | 局部批次修改 | 局部批次修改 | 单仓直接修改 / 需指定仓库 |
| **导出清单** | `export` | 全盘导出 | 导出局部批次 | 导出逻辑集合 | 导出该单仓数据 |

## 6. 语法与解析规则

### 6.1 作用域写法
```
scope  := 空                      全盘（根）
        | 段 ( "/" 段 )*

段     := 维度 分隔符 标识
维度   := "file" | "group" | "tag" | "repo"（默认）
分隔符 := ":"                     输出统一用冒号；输入时 ":" 与 "#" 均兼容
```

### 6.2 规则
1. **绝对路径与相对下钻**：
   - 带有维度前缀（如 `file:D:\repos`、`group:工作`）：属于绝对寻址。
   - 纯名称（如 `cd my-repo`）：在当前节点的直属子项中匹配并向前走一步。
2. **退栈边界保护**：
   - `cd ..` 向上退回时，不会越过磁盘盘符根目录。
   - 到达全局根后，`cd ..` 停留在根，不会报错也不会退出会话。
3. **未命中提示**：
   - 若输入的子目录或分组不存在，不会静默退回全局，而是明确报告未找到并给出可用候选。

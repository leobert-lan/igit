# Scope — 导航式作用域

> 设计稿留痕，别当说明书看。落地版以 README 的**作用域**一节和 USAGE 的 **2.6 作用域**为准。
>
> 落地时改了三处关键决策：
> 1. `focus` **不持久化** —— 改为按当前目录推断的会话内状态，位置不写盘
> 2. 命令**不按节点严格收敛** —— 作用域圈定的是 `ls`/`list`/`pwd`/`triage`/`tree`/`stats`/`export` 的对象，
>    `set`/`open`/`rm` 仍按关键字在全集里找
> 3. `show` / `log` / `check` **尚未实现**，本文档里的命令矩阵是规划不是现状
>
> 没改的部分（序列化语法、跨维度交集、`:` 与 `#` 双分隔符、边界规则表）依然成立。

## 1. 一句话定义

**Scope 是一棵虚拟的树，节点由元信息推导而来，序列成一个字符串；它同时决定"你在哪"和"你能敲什么"。**

grscan 过去是"扫一遍、出一份清单"。加上 Scope 之后，它变成一个可以走进去、在里面移动、越走越细的工作台。

三个维度的路径都能走到同一个仓库 —— 这不是三种过滤方式，是三种**走法**。

## 2. Scope 需要哪些元信息

先穷举元信息，序列化规则是它的自然投影。关键分界是**保质期**：

### 2.1 入串（持久，必须能原样还原）

| 元信息 | 说明 |
|---|---|
| 段序列 | 有序。顺序即来路，决定了 `..` 退到哪 |
| 每段的维度 | `file` / `group` / `tag`（后续可扩展 `state` / `remote`） |
| 每段的标识 | 目录路径 / 分组名 / tag 名 / 仓库名 |
| 来源 | `explicit`（显式 cd）/ `cwd`（当前目录推断）/ `root`（默认） |

### 2.2 不入串（实时，每次解析现算）

| 元信息 | 说明 |
|---|---|
| 节点类型 | 是集合还是仓库 —— 查清单推导，不存 |
| 仓库集合 | 这个 scope 圈住哪些仓库 |
| 子项清单 | 下一层有哪些目录 / 分组 / tag / 仓库 |
| 汇总数字 | 数量、脏、未推送、无上游…… |
| 数据新鲜度 | 距上次扫描多久（只读工具才敢标这个） |

**"无损失"的确切含义**：字符串只需还原"路径语义"，不需要还原"这儿有什么"。后者永远现算，所以 scope 不会因为仓库增删而过时。

## 3. 序列化规则

```
scope  := 空                      虚拟根
        | 段 ( "/" 段 )*

段     := 维度 分隔符 标识
维度   := "file" | "group" | "tag" | "repo"(可省略)
分隔符 := ":"                     输出统一用冒号；解析时 ":" 与 "#" 都接受
```

> **为什么默认 `:` 而不是 `#`**：`#` 在 bash 和 PowerShell 里都是注释符，`grscan cd tag#待推送` 会被 shell 截断，必须加引号。冒号不需要转义。解析器两者都收，输出统一冒号 —— 手写习惯不用改。

| 字符串 | 含义 |
|---|---|
| *(空)* | 虚拟根，全集 |
| `tag:待推送` | tag 集合节点 |
| `tag:待推送/scan_git` | 仓库节点（无前缀段 = 在父范围内匹配仓库） |
| `file:D:\repos` | 该目录下全部仓库 |
| `file:D:\repos\foo` | foo 本身是仓库 → 自动成为仓库节点 |
| `group:工作` | 分组集合节点 |
| `group:工作/tag:待推送` | **交集**：工作分组里打了待推送的 |
| `file:D:\repos/tag:待推送` | **交集**：该目录下待推送的 |

**同维度嵌套 = 下钻，跨维度嵌套 = 交集**，两种语义统一成"在上一步结果里再筛"，规则不用特判。这是语法白送的能力。

## 4. 节点类型与可用命令

| 节点 | `ls` | `list` | `show` | `log` | `check` | `triage` | `set` | `open` | `export` |
|---|:--:|:--:|:--:|:--:|:--:|:--:|:--:|:--:|:--:|
| 虚拟根 `∅` | ✓ | ✓ | — | — | ✓ | ✓ | — | — | ✓ |
| 维度集合 `tag:` `group:` `file:`(目录) | ✓ | ✓ | — | — | ✓ | ✓ | ✓ | — | ✓ |
| 仓库节点 | — | — | ✓ | ✓ | ✓ | — | ✓ | ✓ | ✓ |

命令按层级收敛是好事 —— 在根下误操作不到单个仓库。代价是"不知道这里能做什么"，所以 **`grscan` 不带参数 = 列出当前 scope 的可用动作**，类似 triage 底部那条键位条。

导航三件套沿用 shell 隐喻，零学习成本：

```cmd
grscan cd tag:待推送      进入
grscan cd ..              上一层
grscan cd /               回根
grscan ls                 这个 scope 下有什么
grscan pwd                我在哪
```

**Scope 是叠在所有现有命令之上的约束**，不是新的一套命令。`list --dirty` 在 `tag:待推送` 下 = "待推送里那些有改动的"。现有过滤参数全部保留，只是先被 scope 圈一道。

> 原来构想的 `g show` / `g log` / `g go` 子命令组**不再需要** —— 走进仓库节点后，命令自然可用，不用再加一层命名空间。

## 5. 两个入口与失效规则

用户有两个进入方式，汇合到同一个状态：

- **入口 A（从清单进入）**：`grscan cd <scope>`，cwd 没动，状态必须持久化
- **入口 B（已在目录里）**：靠 cwd 推断，零状态

持久化不是可选项，是 A 逼出来的。存在 `state.json` 的 `focus` 字段（字符串 + 时间 + 来源），看得见就能改，不像隐式状态。

**失效规则：focus 优先，cwd 出界即解除。**

```
focus = file:D:\repos\foo，你 cd 到了 D:\work
  → 提示"已离开 foo，作用域切换为当前目录"，focus 自动清除
```

对应直觉：人走了，焦点跟着走。两个入口不会打架。

## 6. 边界情况（写第一行代码前必须定死）

| # | 情况 | 规则 |
|---|---|---|
| 1 | 路径里的 `\` 与段分隔 `/` | 不冲突。但 Git Bash 风格 `D:/repos` 先规范化成 `D:\repos` |
| 2 | 分组名 / tag 名含 `/` | 会撕裂段。**禁止**，创建时校验并拒绝 |
| 3 | 大小写 | 路径沿用 Windows 不区分；分组与 tag 沿用现有 `EqualFold` 不区分 |
| 4 | `..` 退到哪 | 段内先降一级；没级可降就去整段。`tag:待推送/scan_git` → `tag:待推送` |
| 5 | 一个都没匹配到 | **绝不静默退回全局**。报"当前目录不在扫描范围内"并给建议 —— 你以为在看局部其实在看全局，比报错危险 |
| 6 | 仓库被删 / 移出清单 | 解析失败 → 回退到父节点并提示原因，不崩 |
| 7 | 名字重名 | 维度前缀已经隔离了命名空间：`group:工作` 与 `file:工作` 不冲突 |
| 8 | 空分组 / 空 tag | 保留节点，显示 0 个并提示可清理 |

## 7. 落地分期

现有代码已经铺好了大半，不是从零起：

| 分期 | 内容 | 可复用的现成能力 |
|---|---|---|
| **P0 导航内核** | scope 序列化/解析、`cd`/`ls`/`pwd`、`focus` 持久化 | `util.HasPrefixPath`、`state.Find` |
| **P1 仓库节点** | `show` / `log` / `branches` / `remote` / `open` 传送门 | `gitinfo`、`render.View` |
| **P2 集合节点动作** | `check` / `triage` 限定在当前 scope | `filterRepos`、`tui.Run`（传入已过滤子集即可） |
| **P3 扩展维度** | `state:` / `remote:`（后者 = 现在的 `dupes` 变成可导航） | `StatusList`、`PrimaryURL` 聚合 |

**传送门（`open`）行为暂定**：默认资源管理器；`--in=gui` 起 git gui、`--in=tig` 起 tig、`--in=term` 开终端。工具先探测目标在不在，没装就直说，而不是敲了个没反应的命令。

**写操作的边界不变**：grscan 只"看"，不替你 push。到了仓库节点，是打开界面让你自己动手。
